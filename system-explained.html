04 / Inside the memory engine

Remember with sources.
Recall with context.

Writing preserves what happened and what was accepted. Reading combines semantic matches with graph evidence, time and lifecycle rules. Switch between the two paths below.

Similarity helps find candidates.

Temporal filtering, supersession, disputes and explicit protection determine eligibility. A high similarity score does not make a claim authoritative.

Coordinated writes have a defined limit.

Graph staging and vector snapshots compensate caught failures; they do not form a durable, crash-atomic transaction across both stores. Maintenance preserves distinct facts and episodes.

If interpretation fails or a confirmed requirement is unclear, relevant planning stays blocked until retry, clarification or explicit withdrawal. Waiting does not reapprove the old budget.

Handoffs carry evidence and ownership.

Work cites exact claim versions. A task needs a current execution lease before completion. Handoffs retain completed work and explain what now needs review.

Forgetting invalidates derivatives.

A forget request removes retained event evidence and redacts its journal text; replay of the event ID cannot recreate it. Private backup retention is handled separately.

Replay preserves captured context.

Per-event context history supports inspection. Graph/store and resource aggregates remain latest snapshots, rather than fully reconstructed historical databases.

Unavailable data stays unavailable.

No fixture events replace a failed live source. A ten-second stream heartbeat timeout marks retained data stale and reconnects.

The documented observation window retains up to 500 events and 256 latest contexts and resets on memory-owner restart. Store inspection is bounded and paginated. Provider credentials and identity fingerprints are masked.

07 / Boundaries, research and operation

Built to be inspected.
Explicit about its limits.

Real agent execution and real memory power a local travel demonstration. Evaluation and recovery evidence describe particular runs, configurations and failure conditions.

Access and execution

01
Identity → ownership → scoped memory

The website binds ownership on the server. Shared-service credentials determine user space and actor; agent suggestions remain attributed proposals.

02
One embedded-runtime owner

One process owns embedded stores and journals. Cooperating locks and graph leases serialize writes. The dashboard reads through its publication grant.

03
Hosted inference with explicit mode

NVIDIA NIM executes schema-validated actions in bounded tool loops. Explicit offline mode supports deterministic tests; a hosted failure remains a failure.

04
Preflight, restart and recovery

Startup checks dependencies, ports, graph connectivity and configuration. Controlled restart and recovery checks exist; graph-copy writes and storage durability have practical limits.

What the outputs establish

Kashmir and Kerala catalogs, supplier listings, rates and regional maps are synthetic demonstration data. They do not establish live availability or routing.

B

Website checkout creates status requested. Connected hosted specialists have no booking or payment tool; a plan is not a supplier reservation.

C
Evaluation is reproducible and scoped

DMR, LoCoMo and LongMemEval workflows retain full selected histories, fingerprints, failures and resumable checkpoints. Local metrics differ from official benchmark protocols.

D
Local acceptance has a defined scope

Retained reports cover hosted execution, consistency and controlled recovery. Historical speed results depend on revision and workload; local acceptance does not establish production durability.

A few terms, in plain language
  • Receipt: saved processing state for an incoming source event. Saved can still mean waiting for interpretation.
  • Claim: a versioned assertion with source, scope, acceptance and lifecycle state.
  • Context card: a compact, source-derived view relevant to a task or explicitly stated mood.
  • Context proof: snapshot identity for the evidence and state used to assemble context, checked again after generation.
  • Supersession: an accepted claim replaces an earlier one at its effective time while retaining history.
  • SSE: Server-Sent Events, the ongoing HTTP stream that pushes observations to the dashboard.
